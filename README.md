# AutoHH — Автоматический отклик на вакансии HH.ru с использованием ИИ

Telegram-бот для автоматической рассылки откликов на вакансии HH.ru. Проект использует модель ИИ Gemini для генерации сопроводительных писем и оценки релевантности вакансий на основе вашего резюме.

---

## Важные требования для работы

1. **Минимум 2 резюме на аккаунте**: На вашем аккаунте HH.ru должно быть создано как минимум два резюме. Это техническое требование, необходимое для того, чтобы при клике на кнопку отклика сайт вызывал модальное окно выбора резюме, которое бот использует для привязки.
2. **Авторизация только через Telegram**: Ввод логина (телефона или почты) и кода подтверждения (OTP) осуществляется исключительно через интерфейс Telegram-бота. Консольная авторизация не требуется и полностью удалена из проекта.

---

## Быстрый старт

### 1. Подготовка конфигурации
Скопируйте пример файла конфигурации и переименуйте его:
```bash
cp .env.example .env
```
Откройте файл `.env` в текстовом редакторе и укажите обязательные переменные:
* `TG_BOT_TOKEN` — токен вашего Telegram-бота, полученный у @BotFather.
* `TG_ALLOWED_USERS` — список числовых Telegram ID через запятую, которым разрешен доступ к боту.
* `GEMINI_API_KEY` — API-ключ Gemini, полученный в Google AI Studio.

### 2. Запуск контейнеров
Запустите проект в фоновом режиме через docker-compose:
```bash
docker-compose up -d --build
```

### 3. Авторизация в HH.ru через Telegram
1. Перейдите в ваш Telegram-бот и отправьте команду `/start`.
2. В появившемся меню перейдите в раздел настроек (`⚙️ Settings`) -> `🔑 Login HH`.
3. Введите адрес электронной почты или номер телефона, привязанный к вашему аккаунту HH.ru.
4. После запроса от бота введите одноразовый код (OTP), отправленный вам сервисом HH.ru.
5. Сессия будет автоматически сохранена в директорию `data/`.

## Основные возможности и режимы работы

### Два параллельных режима работы
* **Ручной режим (Manual Run)**: Запускается пользователем кнопкой `▶️ Run` в чате. Позволяет быстро прогнать выбранный поток настроек (Flow) до достижения лимита откликов за запуск или суточного лимита.
* **Режим мониторинга (Monitoring Run)**: Фоновый режим, который отслеживает новые вакансии по расписанию. Бот автоматически модифицирует ссылки поиска, добавляя параметр сортировки по дате (`order_by=publication_time`), чтобы проверять только самые свежие объявления.

### Алгоритм плавающей границы в мониторинге
Фоновый мониторинг работает по оптимизированному алгоритму скользящего окна (sliding boundary):
1. **Инициализация**: При первом включении мониторинга бот открывает выдачу, находит ID самой первой (наиболее свежей) вакансии на странице и запоминает его как начальную границу. На этом шаге бот **не откликается** на старые вакансии и не тратит лимиты/токены.
2. **Фоновые проверки**: При каждой последующей проверке бот запрашивает выдачу. Если первая вакансия совпадает с сохраненным ID границы — бот сразу же завершает проверку (новых вакансий нет). Если вакансии изменились, бот обходит новые вакансии сверху вниз, отправляя отклики, до тех пор, пока не встретит вакансию с ID сохраненной границы.
3. **Сдвиг границы**: По завершении обхода бот сдвигает границу, сохраняя ID самой свежей вакансии текущего запуска в базу данных. Это исключает повторную обработку старых вакансий и экономит ресурсы.

### Тонкая настройка мониторинга
* **Частота проверок (Interval)**: Настраивается прямо в панели мониторинга (15 минут / 30 минут / 1 час / 2 часа).
* **Случайный сдвиг запуска (Jitter)**: Добавляет случайный временной сдвиг (до 15 минут) перед каждым фоновым тиком, размывая четкое расписание и защищая от алгоритмов обнаружения ботов.
* **Праймтайм и умный расчет времени до запуска (Prime Time & Smart Countdown)**: Позволяет ограничить часы работы авто-поиска (например, `08:00 - 20:00`), а также выбрать местный часовой пояс. Если следующий фоновый запуск выпадает на нерабочее время, бот автоматически рассчитает точную разницу во времени до начала рабочего диапазона и покажет человекочитаемый статус: `⏱ Следующий запуск: через 9 ч 8 мин (начало рабочего времени в 08:00 по UTC+3)`.

### Каноническое кэширование по Vacancy ID
* Все проверки истории откликов и кэширование описаний вакансий выполняются по **уникальному числовому ID вакансии**, извлекаемому из ссылок (например, `135695543`). Это защищает от ложных промахов кэша при изменении GET-параметров ссылок (таких как `query` или `hhtmFrom`), генерируемых HH.ru.

### Самовосстанавливающаяся граница по кэшу (Cache-Hit Early Exit)
* Если базовая точка отсчета (якорь) была удалена или заархивирована работодателем и полностью пропала из выдачи HeadHunter, бот больше не будет сканировать все 40 страниц. При обнаружении **2 последовательных закешированных/обработанных вакансий подряд** бот завершит обход и обновит базовую точку, установив её на ID первой встреченной закешированной вакансии. Это существенно экономит ресурсы.

### Черный список компаний (Blacklist) на уровне Flow
* Вы можете настроить черный список работодателей прямо в меню редактирования потока (Flow). Названия вводятся списком через запятую (например, `сбер, яндекс, ооо ромашка`). Бот проверяет работодателя по совпадению подстроки регистронезависимо и мгновенно пропускает вакансию без захода на страницу и отправки ИИ-запросов, кэшируя результат.

### Бесконфликтность и блокировки
* **Изолированные браузеры**: Ручной режим и фоновый мониторинг работают параллельно в независимых контекстах Playwright. Они разделяют сессионный файл `hh_session.json` только для чтения, что предотвращает конфликты авторизации.
* **Асинхронные блокировки в памяти (In-Memory Locking)**: Для предотвращения одновременной обработки одной вакансии ручным и фоновым планировщиками используется `asyncio.Lock`-безопасный диспетчер `VacancyLockManager` в оперативной памяти. Бот атомарно бронирует ID вакансии перед обработкой. В блоке `finally` бронь гарантированно снимается при любом исходе обработки (успех, ошибка, таймаут или отмена задачи).

### Умная фильтрация и ИИ
* **Умное сопроводительное письмо**: Gemini генерирует естественный, краткий текст (2-3 предложения) на основе стека вакансии и содержимого вашего резюме.
* **Приоритет пользовательских промптов**: При редактировании промптов через `📝 Edit Prompts`, пользовательские инструкции автоматически изолируются в специальный блок `START/END OF USER CUSTOM INSTRUCTIONS` с добавлением директивы наивысшего приоритета. Это заставляет ИИ игнорировать любые конфликтующие стандартные правила в пользу ваших явных указаний.
* **Смягченная оценка опыта**: Бот корректно оценивает вакансии с требованием опыта «1-3 года» при наличии у кандидата опыта от 8 месяцев (грейд Junior/Junior+), пропуская отклик дальше с оценкой 6-7 баллов.
* **Автоматический пропуск опросников и тестов**: Если отклик на вакансию требует обязательного прохождения тестов или заполнения анкет (определяется по редиректу на страницу `vacancy_response`), бот отменит отклик и пришлет вам прямую ссылку в чат.
* **Отслеживание вакансий с вопросами (Кнопка `📝 Вопросы`)**: Бот сохраняет пропущенные из-за анкет вакансии. При нажатии на кнопку `📝 Вопросы` бот выводит только **новые** (еще не показанные в чате) вакансии, автоматически помечая их как прочитанные во избежание дублирования.
* **Защита от ловушек (Prompt Injections)**: Бот на уровне кода и через системные промпты ИИ распознает требования тестовых заданий и скрытые в описании вакансии «HR-ловушки» (например, «напишите слово банан в отклике»), автоматически отсекая такие вакансии и выделяя их в чате цитатой.

## Управление через Telegram меню (Reply Keyboard)
Управление ботом полностью переведено на русский язык нижней панели Telegram для удобства использования со смартфона:
* `▶️ Запуск / ⏸ Пауза / ⏹ Стоп` — управление ручным запуском.
* `📂 Потоки` — создание и редактирование потоков настроек: ссылки на поиск, выбор резюме, суточный лимит откликов, лимит на одну сессию (`Target Applies`), минимальные/максимальные паузы, черный список компаний (`🚫 Черный список`) и редактирование промптов ИИ.
* `📊 Статистика` — суточная статистика успешных откликов, ошибок и пропусков.
* `📜 История` — список последних обработанных вакансий с результатами.
* `📝 Вопросы` — вывод новых, еще не просмотренных вакансий, требующих ручного заполнения анкеты.
* `ℹ️ Статус и Инфо` — глобальный системный дашборд реального времени (активный поток, модель ИИ, время, статусы режимов работы, точка отсчета и статистика).
* `⚙️ Настройки` — выбор модели Gemini, авторизация в HH.ru, управление фильтром типов уведомлений (`🔔 Уведомления`), часового пояса (в виде удобной сетки кнопок от UTC-11 до UTC+12), очистка кэша, сброс лимитов.
* `🔍 Мониторинг` — отдельное меню настройки фонового авто-отклика (включение, интервалы проверок, рандомизация, праймтайм).
